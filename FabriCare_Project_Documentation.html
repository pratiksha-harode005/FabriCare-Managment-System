1. Project Overview

FabriCare is a modern laundry and dry cleaning management platform connecting four user roles (Customer, Administrator, Laundry Staff, and Delivery Partner) through a unified real-time order lifecycle. This document defines the actual portal structure, technical architecture, and end-to-end operational workflow.

Project objectives

  • Allow customers to choose laundry services, select items with custom quantities, and place orders with verified pickup address and scheduled time slot.
  • Allow admin to review new orders in real time, accept or reject them, assign pickup executives, and monitor hub throughput.
  • Allow delivery staff to manage assigned pickup tasks, verify customer collection via secure 4-digit email OTP, and confirm handover at the laundry hub.
  • Allow laundry staff to verify garment counts, track live processing stages (Washing, Drying, Ironing), perform quality checks, and pack orders.
  • Assign completed orders for final doorstep delivery, verify delivery OTP, record payment collection, and complete order lifecycle.
  • Maintain one unified order ID with real-time status synchronization across all four portals via Firebase Realtime Database and Django REST APIs.

Technology direction

Layer Technology Responsibility

Backend Django 5.1 · Django REST Framework · SimpleJWT Business logic, role permissions, state machine transitions, REST API endpoints, user authentication and database models.
Database & Realtime Firebase Realtime Database & SQLite / PostgreSQL Instant two-way live sync for active orders, real-time status transitions, OTP security secrets, and persistent relational data storage.

3. End-to-End Order Workflow

Pickup and final delivery are separate operational tasks, but both remain linked to the same master order record and order ID, synchronized in real time across all four portals.

Step Responsible portal Action Example status
1 Customer Customer selects services, items, specifies pickup address and time slot, and confirms order. PENDING / Order Placed
2 Admin Admin reviews incoming order details and accepts or rejects the order. ACCEPTED / REJECTED
3 Admin → Delivery Admin dispatches and assigns an active delivery partner for customer doorstep pickup. PICKUP_ASSIGNED
4 Delivery Partner reaches doorstep, verifies real 4-digit customer OTP sent to email, records bags and weight. PICKED_UP
5 Delivery → Laundry Staff Partner drops garments at laundry hub; staff verifies physical items and confirms receipt. AT_HUB / Received at Hub
6 Laundry Staff Staff advances order through washing, drying, and steam ironing stages with live progress. IN_PROCESSING (Washing/Drying/Ironing)
7 Laundry Staff Staff conducts quality check inspection, bags items, and marks order ready for dispatch. READY_FOR_DELIVERY / Packed
8 Admin / System → Delivery Admin assigns a delivery executive to transport packed clothes from hub to customer. OUT_FOR_DELIVERY
9 Delivery Partner delivers clean clothes at doorstep, verifies 4-digit delivery OTP, and collects payment. DELIVERED / Completed

Exception handling

  • Rejected orders do not proceed to pickup; customer is notified instantly with rejection reason.
  • Failed pickup or delivery attempts (e.g. customer unavailable, wrong address) are recorded with failure reasons and automatically queued for Admin rescheduling.
  • Garments failing quality check inspection are returned to Rework stage with issue comments rather than being packed.
  • Every status transition automatically records timestamp, responsible user ID, and updates Firebase Realtime Database for zero-latency client sync.

4. Technical Architecture

The FabriCare architecture combines a reactive React 18 frontend, Django 5.1 REST Framework for backend business logic, and Firebase Realtime Database for live cross-portal event synchronization.

Layer Technology Responsibility
Frontend React 18 · Vite 6 · Tailwind CSS · Context API Single Page Application (SPA), role-based routing, real-time tracking views, modal dialogs, and responsive layout.
Backend Django 5.1 · Django REST Framework · SimpleJWT Authoritative business rules, permissions validation, user management, order state machine, and RESTful APIs.
Database & Realtime Firebase Realtime Database & SQLite / PostgreSQL High-speed live order synchronization, active delivery task status events, security secrets (OTPs), and relational persistence.
External Services EmailJS REST API · Firebase Storage Automated delivery of real 4-digit customer verification OTPs directly to inbox, and cloud storage for delivery/agent photos.

Database connection & Real-Time Sync

Django connects to the relational database (SQLite in development, PostgreSQL in production) through backend environment variables. Simultaneously, Firebase Realtime Database synchronizes state changes across active browser clients instantaneously without polling.

Security principles

  • Store sensitive credentials (Firebase Admin keys, JWT secret keys, EmailJS tokens) strictly in backend and frontend .env files.
  • Enforce strict Role-Based Access Control (RBAC) on the backend using Django permissions and custom JWT claims.
  • Secure doorstep pickup and delivery handovers using real 4-digit OTPs generated securely and dispatched directly to customer email.
  • Never expose privileged administrative database keys or service credentials in client-side bundles.

Tracking rules

  • Backend validates every status transition against an authoritative state machine before writing to the database.
  • Valid state changes update the relational database and simultaneously broadcast to Firebase Realtime Database.
  • Customer Track Order page listens directly to Firebase nodes for instant, real-time UI updates without polling.
  • Failed quality checks automatically route orders to Rework status with mandatory staff inspection notes.
  • Doorstep pickup and delivery events strictly require 4-digit OTP verification matching the database record.

End-to-end verification checklist

  • A customer can place an order and see it immediately in Customer Dashboard and My Orders.
  • The admin reviews new orders; rejected orders are canceled, and accepted orders can be assigned for pickup.
  • Only the assigned delivery partner sees the task, navigates to customer, and enters the real 4-digit OTP sent to customer email.
  • Pickup confirmation records bag count, approximate weight (kg), and confirms safe handover at the laundry hub.
  • Laundry staff verifies intake, advances stages (Washing, Drying, Ironing), and passes quality check inspection.
  • Completed garments are packed, tagged, and marked Ready for Delivery.
  • Delivery partner delivers clean clothes at customer doorstep and verifies the delivery OTP.
  • The customer visualizer reflects all status updates in real time via Firebase Realtime Database without page refresh.
  • Role permissions, token authentication, and API endpoints are strictly tested and verified.
